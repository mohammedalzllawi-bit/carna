# تدقيق المشروع الحالي

آخر تحديث: 2026-09-28. هذه مراجعة تنفيذية للكود والواجهات والاختبارات، وليست شهادة أمان أو موافقة على إطلاق تجاري. لم تتم إعادة بناء المشروع أو حذف بيانات المستخدمين. MongoDB + Prisma هما قاعدة التنفيذ الحالية حسب طلب تغيير PostgreSQL.

هذه لقطة سبتمبر وتحتفظ بنتائجها التاريخية؛ لا تستخدم حالات Missing القديمة للحكم على إضافات7 أكتوبر. تفاصيل تنفيذ الاشتراكات والمحفظة والطلبات والمفضلة والمحتوى والتقييمات في [تحديث التشغيل](15-subscriptions-wallet-workspaces.md)، ومتطلبات رفع GitHub والإنتاج في [دليل الاستضافة](16-github-deployment.md). لم يكتمل تدقيق أمني شامل للإضافات.

## معنى الحالات

- **Existing**: المسار المذكور موجود ويعمل ضمن الحدود المبينة، وليس إعلاناً بأن المجال كله مكتمل.
- **Partial**: تنفيذ حقيقي لجزء من المتطلب، لكن الرحلة الكاملة ناقصة.
- **Missing**: لا يوجد مسار تشغيلي، حتى لو وجدت جداول أو وثائق تصميم له.
- **Broken**: خلل تم رصده. نفصل بين الإصلاح المتحقق منه والقيود المتبقية.

## التحقق المنفذ

- Prisma validate/generate، وبناء API وWeb وAdmin.
- ESLint للـAPI.
- 16 اختبار وحدة: الأهلية والمالك وموظف المعرض والحساب المحظور والحد الأدنى والتمديد ودقة العملة وArgon2 وتدوير الجلسة ومزود دفع غير مهيأ والفنيين والكتالوج.
- 19 اختبار تكامل: 9 على MongoDB و9 HTTP لتطبيق Nest كامل واختبار Socket.IO فعلي. تشمل المزايدتين المتزامنتين، تكرار المزايدة، نهاية بلا فائز، فائز احتياطي، عدم السحب الزائد، تكرار إشعار دفع موثق، تزامن Refresh، رفض بدء حساب مالي قديم من الصفر، نسخ قواعد المزاد والزيادة الافتراضية، RBAC وإبطال الجلسات والضيف والصيانة وصلاحية قراءة المدفوعات واستقبال بث مزايدة بعد حفظها.
- قواعد اختبارات عشوائية باسم `libya_auctions_test_<uuid>` تُحذف وحدها بعد التحقق من الاسم؛ لا تكتب الاختبارات في بيانات المشروع.
- اختبارات الدفع تستخدم Adapter داخل الاختبار فقط. نجاحها لا يعني اعتماد أي مزود ليبي أو تجربة دفع فعلية.
- تحديث الاعتماد المتأثر في socket.io-client ضمن الإصدار الرئيسي نفسه بعد تقرير npm audit. نتيجة `npm audit` الأخيرة: صفر ثغرات معروفة. فحص الاعتمادات ليس فحص اختراق.
- فحص الخدمات المحلية: Web وAPI وصفحة دخول الإدارة أعادت 200، صفحة المدفوعات المحمية تعيد التوجيه للدخول، API الإدارة يرفض الزائر والكوكي المزور بـ401، وطلب الإدارة من Origin غير موثوق يُرفض بـ403.

## قيود التحقق

- Flutter/Dart SDK غير مثبتين هنا، ولا مجلدات منصة Android/iOS بعد. لم يُشغّل تحليل Dart أو Widget tests أو بناء APK/IPA؛ الكود موجود لكنه غير متحقق على جهاز.
- المتصفح المدمج لم يكن متاحاً في جلسة التحقق؛ لا ندعي screenshots أو اختبار تفاعل بصري أو وصولية.
- محاولة Security scan الآلية تعثرت عند ملف قفل MongoDB المحلي. هذه مراجعة يدوية واختبارات محددة، وليست تقرير Security scan مكتمل.
- مسار BullMQ/Redis الإنتاجي ليس مسار التشغيل المحلي المختبر؛ المحلي يستخدم polling، ويتطلب الإنتاج Redis واختبار الاستعادة والتكرار والضغط.
- التسجيل حالياً يبقي الحساب PendingVerification؛ لا تُشغّل مزايدات عامة بالتحقق اليدوي بديلاً عن منظومة OTP المعتمدة.

## التشغيل والترقية

1. احتفظ بنسخة احتياطية قبل ترقية قاعدة موجودة. أوقف عمليات الكتابة أثناء الترقية، ولا تستخدم `--accept-data-loss` أو تحذف مجلد البيانات.
2. `npm.cmd run prisma:generate --workspace @libya-auctions/api` ثم `npm.cmd run db:upgrade` لتعبئة حقول النسخ والقفل ومفاتيح التكرار والفهارس دون حذف سجلات. تحتاج القاعدة الجديدة أيضاً `db:push` قبل seed.
3. `npm.cmd run prisma:seed --workspace @libya-auctions/api` للأدوار والصلاحيات والمرجعيات. لا ينشئ Seed سيارات أو أرصدة وهمية.
4. `npm.cmd run admin:bootstrap` مرة واحدة لإنشاء أول مدير برقمك وكلمة مرورك. لا كلمة مرور افتراضية ولا مشاركة لمفتاح الإدارة مع المتصفح.
5. أي مزاد قديم بلا `ruleSnapshot` يحتاج مراجعة القواعد قبل التسوية؛ السكربت يحذّر ولا يخترع رسومه. أي Ledger سابق بلا WalletAccount يحتاج مطابقة مالية قبل استقبال حركات جديدة.
6. البيئة الفعلية: `apps/api/.env`، و`apps/web/.env.local`، و`apps/admin/.env.local`. ملف الجذر وحده لا يضبط التطبيقات الثلاثة.
7. التشغيل: MongoDB 27018، API 4100، Web 3100، Admin 3101. لا تُوقف خدمة أخرى لتفريغ منفذ ولا تستخدم 3000 لهذا المشروع.

## الأولوية التالية

1. OTP واستعادة الحساب وMFA للإدارة، ثم شروط بإصدارات وموافقة موثقة.
2. رفع وسائط ووثائق آمن مع ملكية وتوقيع وفحص؛ تفاصيل مركبة حقيقية كاملة.
3. اعتماد مزود دفع رسمي مع reconciliation وRefund وإيصال واختبارات Sandbox. لا تفعيل مدفوعات قبل إكمال ذلك.
4. بوابة المعرض وخططه وموظفيه، ثم رحلة الفحص والتقرير وحساب الفني والنزاع والدعم.
5. استكمال Flutter وتجربته، مراجعة UX، حملات وتنبيهات وتقارير، ثم اختبارات ضغط ونسخ احتياطي واستعادة وتدقيق مستقل قبل الإطلاق.
