# جاهزية الإطلاق

## الحالة الحالية

تحديث 2026-10-07: راجع [الاشتراكات والمحفظة والطلبات](15-subscriptions-wallet-workspaces.md) و[الاستضافة](16-github-deployment.md) للإضافات الجديدة وحدودها. الاختبارات الحالية نجحت:87 وحدة خادم،37 تكامل Mongo/HTTP،16 واجهة Flutter و2 لأوامر الاستضافة، مع نجاح بناء الويب والإدارة. هذا لا يلغي موانع الإطلاق المالي أو الحاجة إلى مراجعة أمنية شاملة.

المشروع الآن قاعدة MVP تشغيلية وليست بعد نسخة جاهزة لإطلاق تجاري عام. البيانات المعروضة في الكتالوج ولوحة الإدارة تأتي من MongoDB، ولا يتم إنشاء سيارات أو مزادات تجريبية تلقائياً.

التفاصيل بحسب كل متطلب وحالة الاختبارات والقيود في [تقرير التدقيق](12-project-audit.md). وثائق البنية القديمة تصف أيضاً وظائف مخططة، ولا تعني اكتمال تنفيذها.

المتاح حالياً:

- تسجيل مستخدم جديد وتسجيل الدخول والدخول كضيف للقراءة فقط.
- جلسة Web آمنة باستخدام Cookies من نوع HttpOnly مع تدوير Refresh Token.
- إدارة المستخدمين وحالاتهم وأدوارهم من لوحة الإدارة.
- إضافة الفنيين، ومنهم كهربائيو السيارات، وتحديد خدماتهم وأسعارهم ومدنهم ثم مراجعتهم ونشرهم.
- إدارة المدن والسيارات ومراجعة السيارات ونشرها أو أرشفتها.
- كتالوج عام للسيارات والفنيين يعتمد على REST API الفعلي.
- خدمات أساسية للمزاد والدفع واختبارات لقواعد المزايدة، انتهاء المزاد، العربون، وتكرار Webhook.
- تطبيق Flutter ببيانات API وتدفق تسجيل/ضيف؛ نجحت اختبارات الواجهات وبناء Android التجريبي. توقيع المتجر وiOS واختبار الإشعارات الفعلية على الجهاز من متطلبات الإصدار التجاري.
- تحقق إلزامي من متغيرات البيئة، مع رفض أسرار التطوير وعناوين قواعد البيانات المحلية في وضع Production.

## موانع الإطلاق التجاري

يجب إكمال البنود التالية قبل استقبال أموال أو مزايدات حقيقية:

1. التعاقد مع مزود دفع ليبي والحصول على وثائق API الرسمية وبيانات التاجر ومفاتيح Webhook، ثم اختبار الدفع والاسترداد في Sandbox المزود.
2. ربط مزود SMS رسمي لتوثيق رقم الهاتف واستعادة الحساب، وعدم السماح بالمزايدة قبل اكتمال التوثيق المطلوب.
3. إضافة MFA للإدارة. تم تنفيذ تسجيل الدخول الإداري وRBAC والجلسات القابلة للإبطال وإيقاف المفتاح القديم افتراضياً وحظره في الإنتاج.
4. تشغيل MongoDB Replica Set مُدار، وRedis مُدار، وObject Storage خاص مع Signed URLs وفحص الملفات.
5. توسيع واجهة المزايدة الحية الموجودة عبر Socket.IO واختبارات الضغط والانقطاع وإعادة الاتصال على بيئة مماثلة للإنتاج؛ اختبارات التزامن الأساسية لا تغني عن اختبار الحمل.
6. استكمال المعارض والاشتراكات والفحوصات والإعلانات والنزاعات والتسوية المالية؛ الإدارة الحالية تشمل المستخدمين والسيارات والفنيين والمدن والمزادات والأدوار والإعدادات وسجل التدقيق وقراءة المدفوعات.
7. مراجعة قانونية ليبية لشروط المزاد وسياسة الخصوصية وحماية المستهلك والإرجاع والاحتفاظ بالبيانات.
8. إعداد HTTPS وWAF وRate Limiting موزع ومراقبة الأخطاء والسجلات والتنبيهات والنسخ الاحتياطي المجرب وخطة التعافي.
9. بناء تطبيق Android وiOS وتوقيعه، واختبار Push Notifications وDeep Links وسياسة حذف الحساب على أجهزة حقيقية.
10. تنفيذ اختبارات قبول وأمان واختبار اختراق ومراجعة صلاحيات مستقلة قبل فتح النظام للجمهور.

## متغيرات الإنتاج

استخدم ملفات الأمثلة التالية كقائمة حقول فقط:

- `apps/api/.env.production.example`
- `apps/web/.env.production.example`
- `apps/admin/.env.production.example`

لا تنسخ الأسرار الحقيقية إلى Git أو إلى Frontend. خزّنها في مدير أسرار منصة الاستضافة. لوحة الإدارة تستخدم جلسة المستخدم ولا تحتاج `ADMIN_API_KEY`. المتغير `NEXT_PUBLIC_WEB_URL` عنوان عام للموقع وليس سراً. الإنتاج يتطلب `AUCTION_WORKER_MODE=redis` و`ALLOW_LEGACY_ADMIN_KEY=false`.

لتوليد سر قوي في PowerShell:

```powershell
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

## بوابة الإطلاق

لا يُعتمد الإصدار للإطلاق إلا بعد نجاح البناء والاختبارات، تجربة الدفع الفعلية في Sandbox، اختبار مزايدين متزامنين تحت الضغط، نجاح استعادة نسخة احتياطية، وتوقيع المسؤول التقني والقانوني على قائمة الموانع أعلاه.
