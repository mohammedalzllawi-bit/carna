# منصة مزادات السيارات الليبية

منصة رقمية متعددة التطبيقات لبيع وشراء المركبات عبر المزادات الإلكترونية والسعر الثابت والبيع السريع، مصممة للسوق الليبي بعملة LYD، وتجربة عربية RTL من البداية.

## النطاق التشغيلي الحالي

**المشروع قيد التطوير، وليس جاهزاً بعد لاستقبال أموال أو مزايدات تجارية.** راجع [تقرير التدقيق وحالة جميع المتطلبات](docs/12-project-audit.md) و[موانع الإطلاق](docs/11-launch-readiness.md).

التحديث الحالي يضيف اشتراكات نشر الأفراد، المحفظة والاسترداد، واجهات طلبات البائع والفني والمعرض، المفضلة وتذكيرات المزاد، وإدارة الشروط والتقييمات. راجع [تفاصيل التشغيل والصلاحيات](docs/15-subscriptions-wallet-workspaces.md) و[تجهيز GitHub والاستضافة](docs/16-github-deployment.md). أقسام الإدارة الجديدة في `/operations`، وحساب الويب في `/workspace`.

لنشر Railway: `railpack.json` في الجذر يبني API ويشغله عبر `npm start`. أنشئ خدمتي Web/Admin منفصلتين من الجذر، مع `RAILPACK_CONFIG_FILE=deploy/railpack.web.json` أو `deploy/railpack.admin.json`، وأدخل متغيرات الإنتاج في الاستضافة. راجع جدول الإعدادات في [دليل النشر](docs/16-github-deployment.md#railway-وrailpack).

هذه النسخة تستخدم MongoDB فعلياً. قد تحتوي قاعدة التطوير على عينتين تجريبيتين إذا شُغّل `seed:demo`؛ لا تستخدم بيانات التجربة في الإنتاج. المسار التشغيلي الحالي هو:

- إضافة السيارة من لوحة الإدارة وحفظها كمسودة.
- تعديل بيانات السيارة أو أرشفتها مع إنشاء Audit Log.
- نشر السيارة بعد المراجعة.
- ظهور السيارة المنشورة في الموقع وتطبيق Flutter عبر نفس REST API.
- إدارة المدن وتفعيلها أو إيقافها من لوحة الإدارة.
- إحصاءات الإدارة تُحتسب مباشرة من قاعدة البيانات.
- دخول الإدارة بحساب وصلاحيات، وإدارة أدوار مخصصة وسجل تدقيق وإعدادات تشغيل.
- مزاد حي وقواعد ذرية وفائز وعربون وLedger داخلي؛ مزودات الدفع الحقيقية لا تزال معطلة حتى اعتماد التكامل الرسمي.
- عميل Resala للخادم وتوثيق هاتف OTP مع اختبار آمن خارج الإنتاج؛ يحتاج إلى مفتاح API فعلي قبل إرسال أي رسالة. راجع [إعداد Resala](docs/13-resala-sms-otp.md).
- متابعة المدفوعات وأحداث المزود من لوحة الإدارة بصلاحية مالية مستقلة، دون زر لتأكيد الدفع يدوياً.
- يستطيع المستخدم المسجل إضافة إعلان بيع مباشر مختصر لسيارة أو شاحنة أو دراجة نارية أو هوائية أو فئة أخرى. يحفظ كمسودة، يتطلب صورة، ثم ينتقل إلى مراجعة الإدارة قبل ظهوره للعموم. يمكن إكمال المسودات من الموقع والتطبيق.
- البحث العام يدعم التصنيف، الاسم، الموديل، تاريخ النشر، والترتيب بالأحدث أو الأقدم أو السعر. تعرض صفحة التفاصيل زر اتصال عند توفر رقم البائع ومحادثة داخل المنصة للحسابات المسجلة.

## التشغيل المحلي المقترح

```powershell
npm.cmd install
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm.cmd run db:dev
npm.cmd run prisma:validate --workspace @libya-auctions/api
npm.cmd run prisma:generate --workspace @libya-auctions/api
npm.cmd run db:push
npm.cmd run prisma:seed --workspace @libya-auctions/api
npm.cmd run db:upgrade
npm.cmd run admin:bootstrap
npm.cmd run api:dev
npm.cmd run web:dev
npm.cmd run admin:dev
```

شغّل أوامر `db:dev` و`api:dev` و`web:dev` و`admin:dev` في نوافذ PowerShell منفصلة. لوحة الإدارة متاحة على `http://localhost:3101`، ومن قسم **إدارة المركبات** يمكن مراجعة إعلانات المستخدمين ونشرها لتظهر على `http://localhost:3100`. صفحة نشر البيع المباشر هي `/sell`، وصفحة المزاد المدفوع هي `/sell/auction`.

`admin:bootstrap` مخصص لإنشاء أول مدير فقط؛ يسأل عن رقم هاتفك وكلمة مرور من 12 إلى 72 محرفاً. لقاعدة موجودة، خذ نسخة احتياطية وأوقف الكتابة قبل `db:upgrade` ولا توافق على حذف بيانات عند تحديث المخطط. إعدادات التطبيقات تُقرأ من ملفاتها المحلية، وليس من `.env` في الجذر وحده. لا تشغّل نسخة ثانية من خدمة قائمة على نفس المنفذ.

بعد تحديث مخطط MongoDB شغّل `db:upgrade` أيضاً: فهو يثبت فهرس البريد الإلكتروني الجزئي الذي يسمح بحسابات الهاتف دون بريد، مع منع تكرار البريد عند إدخاله. لا تضع كلمات مرور الحسابات في ملفات البيئة أو الكود.

أمر `api:dev` يعمل بوضع مستقر دون إعادة تشغيل تلقائية لتجنب تعارض العمليات على Windows. بعد تعديل كود الـAPI أوقفه بـ `Ctrl+C` ثم شغله من جديد. يتوفر `npm.cmd run dev:watch --workspace @libya-auctions/api` اختيارياً عندما تكون مراقبة الملفات مطلوبة.

مدينة بنغازي ومناطقها فقط تُضاف عبر Seed كبيانات مرجعية. لا يقوم Seed بإنشاء سيارات أو مزادات وهمية.

يشغّل `db:dev` نسخة MongoDB Replica Set محلية كعملية Node.js على المنفذ `27018` مع حفظ البيانات داخل `.data/mongodb`. يعمل API على `4100`، والموقع على `3100`، ولوحة الإدارة على `3101`. المنفذ `3000` غير مستخدم من المشروع.

ملف `.env` في الجذر محلي وغير متتبع في Git. يجب استبدال أسرار التطوير بقيم قوية ومخزنة في مدير أسرار قبل أي نشر.

> على Windows/PowerShell قد تحتاج إلى استخدام `npm.cmd` بدل `npm` إذا كانت سياسة تنفيذ السكربتات تمنع `npm.ps1`.

## قرارات أساسية

- كل منطق المزادات والدفع والصلاحيات داخل Backend فقط.
- قواعد العربون والتمديد والمهلة ورسوم الشراء ورسوم إدخال المستخدم للمزاد ديناميكية عبر Settings. توجد إدارة كاملة لخطط المعارض وإنشاء حساب المالك والاشتراك والتجديد وتغيير الخطة والتذكير، مع بوابة معرض لإدارة الملف والسيارات. `Fees` و`CommissionRules` العامة ما زالت تحتاج محررات مستقلة.
- يمكن إنشاء جولة مزاد سريعة مدتها الافتراضية 120 ثانية، ويتجدد وقت النهاية بعد كل مزايدة مقبولة. تضبط المدة من `auction.round_seconds` في لوحة الإعدادات؛ المزادات القديمة ذات موعد النهاية الثابت لا تتغير.
- تشترط المزايدة رصيد محفظة افتراضياً قدره 100 د.ل، أو نسبة من السعر الاحتياطي/الابتدائي يحددها المدير عبر `auction.bid_wallet_mode` و`auction.bid_wallet_fixed_milli` و`auction.bid_wallet_basis_points`. القيم المالية في الإعدادات بوحدة مِلّي دينار؛ التحقق من الرصيد لا يخصم مالاً. الشحن الذاتي متوقف حتى تفعيل مزود دفع رسمي، وتبقى التعديلات الإدارية موثقة في سجل المحفظة.
- لا يتم تأكيد الدفع من Frontend؛ التأكيد يتم عبر Webhooks موثقة وموقعة.
- سجلات المزايدات والمدفوعات والـ Audit Log لا تحذف نهائياً، بل تؤرشف أو تلغى منطقياً.
- العربية RTL مدعومة؛ الترجمة الشاملة وإدارة جميع النصوص من Dashboard لم تكتمل بعد.

## الإشعارات والمحادثات

- مركز الإشعارات متاح للحسابات المسجلة على الويب والتطبيق. من لوحة الإدارة افتح `/notifications` لضبط الإشعارات الفورية والمجدولة والمزادات والرسائل، وإرسال إشعار مخصص أو تجريبي ومتابعة حالة Push. راقب المحادثات من `/messages` بصلاحية الدعم؛ يُسجَّل فتح كل محادثة في Audit Log.
- لتفعيل Push على Android، أبقِ `apps/mobile/android/app/google-services.json` مطابقاً لحزمة التطبيق، وأضف إلى بيئة **خادم API** `FIREBASE_PROJECT_ID=karna-2ab13` و`GOOGLE_APPLICATION_CREDENTIALS` بمسار مطلق إلى ملف Service Account من مشروع Firebase نفسه. احتفظ بالملف خارج المستودع ولا تضعه في الويب أو تطبيق الهاتف. تحتاج أيضاً تفعيل Firebase Cloud Messaging API في المشروع ومنح التطبيق إذن الإشعارات. ستعرض لوحة الإدارة سبب عدم جاهزية Firebase إن نقص أحد الإعدادين. ملف Android وحده لا يكفي لإرسال الخادم.
- الاختبار من لوحة الإدارة ينشئ إشعاراً في حساب المدير. لاختبار وصول Push للهاتف، سجّل دخول الحساب نفسه على الجهاز، وافق على الإشعارات، تأكد من ظهور الجهاز في اللوحة، ثم أرسل إشعاراً مخصصاً إلى الحساب أو استخدم زر الاختبار لحساب الإدارة. راقب حالة `Sent` أو `Failed`؛ إنشاء سجل In-App لا يعني وصول Push. الإشعارات المجدولة تُسلّم عندما يعمل خادم API وتصبح مستحقة.
- الرسائل الصوتية مدعومة داخل المحادثة للحسابات المسجلة، بحد أقصى 60 ثانية و4 MB على الخادم. التخزين الخاص الموقّع يتطلب `MEDIA_STORAGE_PROVIDER=cloudinary` ومفاتيح Cloudinary صحيحة. لا تُخزّن الملفات الصوتية داخل MongoDB. بناء iOS وإعداد APNs/Firebase له يحتاج مشروع iOS وإعداداته منفصلين؛ هذا المستودع يحتوي Android حالياً.

اختبارات التكامل تحتاج MongoDB Replica Set يعمل، وتستخدم قواعد اختبار منفصلة تمسحها بعد الاختبار فقط. بناء Flutter غير متحقق حتى تثبيت SDK وإعداد منصتي Android/iOS.
